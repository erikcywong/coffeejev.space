02 / THE THREE JUDGERS

同一套数学，装在手机里The same mathematics, in your hand

与网页版、以及 service/ 里的 Python 参考实现完全一致 —— 换的是外壳，不是算法。

Identical to the web edition and to the Python reference in service/. The shell changes; the algorithm does not.

A · 污染 NoulA · Contamination

noul

校准后的概率，配上由成本推导的阈值，再加一条运营下限，让阈值在真实车间里可执行。

A calibrated probability, a cost-derived threshold, plus an operating floor so the threshold is actually executable.

τ_cost = C_FP / (C_FP + C_FN) → 4.3% τ_hi = max(τ_cost, τ_min) → 15% 三区间：[0,τ_lo) 放行 · [τ_lo,τ_hi) 复核 · [τ_hi,1] 处置

B · 驯化 ScoreB · Readiness

score

六项加权打分，但硬闸门会直接压分：根数不足 3，再好的叶色也不会放行。

Six weighted sub-scores, but hard gates cap the result: fewer than three roots and great leaf colour will not release it.

score = Σ wᵢ·sᵢ w = 22/20/10/12/18/18 % caps: roots<3 → ≤55 · browning>60 → ≤60 · p≥0.5 → ≤40 band: ≥80 可移栽 · 60–79 延迟 · <60 继续

C · 营养雾 ChoiceC · Nutrient fog

choice

先过硬约束，再算效用，最后在可行解上做 softmax —— 没有可行解时输出停止并复核。

Hard constraints first, then utility, then a softmax over the feasible set. Nothing feasible → stop and review.

04 / REVIEW & LEDGER

人放在正确的价位上People at the right price point

复核队列Review queue

每条待办都带证据与理由分类。三种动作：采纳、改判、要求补证 —— 都会写进账本。

Every item carries evidence and a reason code. Three actions — accept, override, ask for evidence — all land in the ledger.

哈希链账本Hash-chained ledger

每次判断记录 prev 与 hash，页面上可直接验证链是否完整；被改动过就会标红。

Each judgement stores prev and hash; the app verifies the chain in place and turns red if anything was altered.

经济性Economics

回收期、年净现金流、单次决策成本三项直接算在设备上，公式与网页版一致。

Payback, annual net cash flow and cost per decision, computed on device with the same formulas as the web edition.
