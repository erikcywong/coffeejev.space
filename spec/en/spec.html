01 / DESIGN REVIEW

Design review

The v0.1 draft was right about the framing — and thin on the engineering

The review takes four dimensions: decidability (is the input enough to decide), Enforceability (can the decision land on the floor), Learnability (does landing it make the system stronger), Deliverability (will it hold up in production). v0.1 is most complete on decidability; the gaps cluster in the last three.

1.2 Twelve gaps Sort by "what will happen if you don't make up for it", not by how good it looks.

G01

Only stage, no batch lineage

Enforceability
in the draft stage It is a string, but once contamination occurs, what really needs to be answered is "which disks should be isolated, how many shelves are affected, and which batch of mother plants should be deactivated." No batch_id → mother plant → tray → shelf → aeroponic trough In the lineage diagram, the isolation radius cannot be calculated, and the whole greenhouse can only be shut down - this is the most expensive failure mode of aeroponics.
lineage diagram + contamination events along the diagram BFS gets isolation radius; put blast_radius Enter Choice as an independent candidate action (how many disks to isolate is a decision in itself).
G02

Confidence is not defined and not calibrated

Deliverability
In the draft example confidence: 0.82 Directly from model softmax. Vision model generalizes outside training distribution Overconfidence (Deep network ECE is often 0.1–0.2), so 0.82 may correspond to a true accuracy of 0.55. Using it as a threshold is equivalent to using a dashboard without scale for surgery.
calibration layer（temperature scaling / isotonic）+ ECE and reliability diagram Online monitoring + abstention mechanism (Conformal prediction set: it will be upgraded directly when two candidates are output).
G03

The binary decision of "contamination" is too rough. Even if the decision is correct, it may be wrong.

decidability
Bacteria, fungi, vitrification, mites, viruses, the actions are completely different: bacteria → complete destruction + countertop disinfection; fungi → isolation + dehumidification + ventilation; vitrification → hormone reduction + increase ventilation; mites → full layer treatment. Binary output compresses five treatments into one true, the downstream can only rely on human memory to complete it.
Noul expands to 5+1 category (5 diseases + 1 abiotic stress), and output time dimension (First visible → irreversible remaining days), the action template is automatically bound with the category.
G04

The label arrives late and there is no room for it in the pipeline

Learnability
Contamination labels arrive in 7–14 days, and transplant survival occurs in 30–45 days. The draft says "use the survival rate for reshoring", but there is no component that undertakes "make decisions today and know what is right or wrong next month." The result is inevitably to use proxy labels, and the calibration drifts with the seasons.
delayed tag table (decision event + label_ready_at + backfill tasks) + dual track label: Final label for training and proxy label for monitoring.
G05

The sensor itself cannot be trusted, but there is no quality gate

Deliverability
The EC/pH probe is covered with biofilm within a week or two; the pH electrode drifts faster in low ionic strength nutrient mist; the camera fogs and condensates. A set of decision layers that "believe all input" will be given in the week when the probe breaks Very confident wrong decision.
perceptual layer plus sensor_health (drift rate / response time / dual probe cross-check / replacement cycle), any need_more_info Or abstain and never use it silently.
G06

"It is recommended to adjust the nutritional mist" does not fall on the valve

Enforceability
The draft draws the boundary correctly (human confirmation for critical actions) but has no mechanical design on the execution side: nobody confirms the instruction was carried out, nobody reads it back, nobody rolls back when the read-back drifts. Decision and floor stay one step apart, and attribution breaks.
Command → Gateway ACK → Read back the actual measurement after 30s → Rollback + alarm if the deviation exceeds the limit;The hard limit (EC/pH/pressure/atomization duty cycle) sinks to the PLC and cannot be crossed by the software layer.
G07

Without golden sets and replays, changing the threshold is just gambling.

Learnability
When the threshold is adjusted from 0.7 to 0.6, does it get better or worse? Without historical replay and cost-weighted confusion matrix, we can only rely on "feeling that there has been less contamination recently". The most common way to die for this type of project is Can't prove that I'm getting better.
Decision replay (Historical Sensor + Image Rerun) + Cost Weighted Loss + shadow mode; Promotion threshold: net income does not decrease And ECE does not rise.
G08

human_review is a Boolean and has no place to implement.

Enforceability
marked as true What happens next? Who reads it, how long does it take to read it, and how do you record those who disagree? Without queues and reasoned categorization, reviewing data is throwing it away—and that’s exactly what the most expensive tags are.
Review queue + 4 types of reasons (image cannot be judged / beyond SOP / first scene / high value batch) + adopt and change binary records → directly enter the training set.
G09

objective has weights but no cost function

Deliverability
The largest variable cost of aerosol cultivation is electricity (Atomization pump, dehumidification, light fill, water cooling). Choice that only optimizes the survival rate will converge to an absurd solution: always open the fog and push the EC to the upper limit. draft {survival, cost, quality} The weight is there, but there is nothing to measure the cost.
Each candidate action carries (kWh, water L, nutrient salt g, artificial min) Cost vector; Choice output Pareto front Instead of a single scalar, the point is selected by the business scenario (contract quality vs. mass production).
G10

No cold start plan for new farms/new varieties

Learnability
The draft says "to establish baselines according to varieties/production areas", but it does not say how to establish them. Training models individually for each farm will inevitably overfit on farms with only a few batches of data; while a global model will erase regional differences.
Hierarchical partial pooling: Breed-level shared prior + farm-level offset (can be estimated with a small number of samples); OOD detection (feature distance/energy score); new scenarios force the shadow to run for 30 days before being released.
G11

Compliance, auditing and data sovereignty are not part of the architecture

Deliverability
Tissue culture materials involve variety rights and plant quarantine; cross-border deployment involves data localization; nutrient solution discharge has legal limits. As for "why this batch of seedlings were judged to be transplantable at that time", we need to provide evidence in the future.
Appending Hash Chain Decision Ledger (decision + input snapshot hash + model_id + SOP version) + data binning (original images are not exported, only gradients/statistics).
G12

0.7 / 80 / 60 These thresholds have no source

decidability
"escalate below 0.7 confidence" and "transplant at ≥80" are guesses. The same 0.7 means completely different losses at the shoot stage and before transplant. The threshold should be cost structure function, is not a constant.
Threshold = cost ratio τ_cost = C_FP /(C_FP + C_FN), Then take the larger of the operating lower limit τ_hi = max(τ_cost, τ_min)— Otherwise the pure cost solution will degenerate into "almost complete isolation"; three intervals (Disposal/Review/Release) instead of binary; use decision curve analysis to see net benefits.

1.3 Three technical judgments that must be revised It's not a supplement, it's a directional correction.

C1 The rule of "upgrade only with low confidence" itself has loopholes high

Sampling only based on confidence level will systematically miss out high confidence error—That’s the really expensive mistake: the model confidently labels an entire class of emerging mites as “healthy.”

Correction: The upgrade strategy must incorporate three dimensions orthogonal to confidence - OOD score, Daily random blind review (Select 20 high-confidence decisions), and provide category-specific accuracy alerts. What is to be monitored is silent error rate, not the average confidence.

C2: "<300 ms" cannot be a system-wide SLA in

The end-side image decision can be within 300ms; however, a nutrition fog Choice needs to integrate timing, cost, constraints and multiple objectives. The cloud p95 is 1.5-2s; expert review is hour-level. Promising a full link with one number will break your promise on the first demonstration.

Correction: Three-level SLA - quick decision on both end and side ≤300ms (p95), cloud integration ≤2s (p95), expert upgrade ≤24h (SLA not latency). Each level has independent monitoring and independent alarm.

C3 "2000 images" are not enough to train contamination decision high

Contamination is a rare event (3-8%). There are only 60-160 positive cases in 2000 pictures. After being divided into 5 disease categories, there are more than a dozen pictures in each category —Can't even hold the validation set, let alone calibration.

Correction: Starting with 5–8k images + active learning to pick boundary samples + synthetic enhancement of fog/condensation/reflection + LIMS recording for weak supervision ("This disk was destroyed" is also a label); first in order Shadow runs for 30 days Let’s talk about going online.

Keep list (things that should not be touched in v0.1)

① Not to be a chatbot, only to be a decision layer - this choice is the most valuable sentence in the entire design. ② The Noul/Choice/Score trichotomy is sufficient to express 90% of agronomic decisions and is naturally verifiable. ③ Structured JSON contract - allows the decision layer to be orchestrated, replayed, and audited. ④ "Retain artificial gates for key actions" - in the biomanufacturing scenario, this is not conservative, but product competitiveness.

02 / FULL-STACK ARCHITECTURE

Architecture

Seven layers, a fast path, a slow path, and one ledger

The draft's six layers are right, but it puts execution and feedback in the same bracket. In a real system those are two different physical paths: one has to land on a valve within 300 ms and be read back, the other waits 30–45 days for labels to arrive. Designing them separately is the biggest structural difference between this architecture and the draft.

2.4 Three deployment topologies The same decision layer, three delivery forms

T1 single farm MVP

Edge box ×2 (active and backup) + farm local server (MinIO + Timescale + orchestration). The cloud is only there Model distribution appears, reasoning and decision-making are all local.

Cost: No cross-site learning; Benefit: It can run for 72 hours when disconnected from the network, zero data is exported, and the deployment is completed in one day.

T2 area multi-farm scale

The farm retains collection and rapid decision; the regional cloud is responsible for integrated decision, cross-field lineage (the same mother plant bank provides seedlings) and centralized review queue. The images stay on site, while features and decisions are uploaded to the cloud.

Cost: regional cloud operation and maintenance; benefit: new farms rely on shared prior cold start, and review manpower is concentrated.

T3 cross-border federation export

Data classification: L0 original image (not exported), L1 feature vector (can export), L2 model parameters (managed). Federated aggregation only moves L1/L2, and local model registries are upgraded separately.

Cost: Engineering complexity; Benefit: Satisfying data sovereignty and variety rights review while sharing global experience.

Three cross-cutting abilities (must be present at every level, not just for one level)

  • safety interlock: The hard limits of EC/pH/pressure/duty cycle are in the PLC, and the software layer only sends instructions; any out-of-bounds instructions are directly rejected and recorded on the gateway side.
  • Observability: Each decision zone trace_id, through collection → reasoning → strategy → execution → review; indicators are sliced according to "judger × variety × farm".
  • auditable: Decisions, input snapshot hashes, model versions, SOP versions, and review results are all entered into the chain; the ledger is only appended, and the export is the voucher.

3.1 Why are these three stars marked? acclimation readiness is the “exchange rate” of the entire chain

⑥ acclimation readiness connect

It is between tissue culture and aerosol culture unique exchange rate: set it loose and the aeroponic side eats the mortality; set it tight and the culture side piles up stock with cost trapped in jars. The threshold moves the economics of both lines, so it must be Downstream survival rate Counter-calibration, rather than setting it by the tissue culture workshop itself.

⑦ Transplanting gate Irreversible

Out of the bottle is Irreversible operation: Once contamination is brought into the aeroponic trough, it will be a risk to the entire tank. So here the default human_review=true, AI is only responsible for "suggestion + sorting + picking out things that should not be moved", and is not responsible for releasing. New varieties transplanted for the first time must be transplanted manually.

⑧ Nutritional mist formula high frequency

It may be triggered dozens of times a day, making it the most suitable node for "quick decision" and the node most prone to accidents (the root tip can be burned if the EC is raised for 20 minutes). Design points: The hard limit is in the PLC and the software only sends pictures, and each adjustment must be able to be rolled back.

5.2 Response fields and status semantics

Response header fields

  • decision — single value enumeration, No natural language
  • confidence — After calibration Confidence (see 7.2), not softmax original value
  • scores — Internal key quantities of the judge (p, τ, readiness, utility...), used for post hoc attribution
  • options[] — Candidate actions, feasibility, utility, probability
  • human_review + review_reasons[] — More to say besides Boolean why
  • reason — ≤80 words, just explain why people who don’t read the data should believe/should be suspicious
  • evidence_refs[] — Image/sensor snapshot hashing to support traceability
  • audit_id — Hash chain ledger index, can be played back if problems arise

The four types of "non-decision" are also official outputs

  • need_more_info — Missing fields or insufficient sensor health. 200 return, not 400
  • abstain — Still in the review area after calibration and unable to re-certify (conformal set contains more than two categories)
  • stop_and_review — All candidate actions violate hard constraints and do not allow the system to choose on its own
  • defer_to_human — First time scenario/new variety/high value batch, forced by policy

It is cheaper to make "no decision" into a legal output than to force the model to give an answer - this is the dividing line between the decision layer and the chat robot.

07 / LEARNING LOOP

Learning loop

Labels arrive late, so the loop is designed to be asynchronous

This is the section most easily skipped, and the one most likely to leave the system dead in six months. The idea: do not try to make the model learn in real time; instead make every judgement leave a settleable receipt and settle in batches once the labels arrive.

7.1 Five-step closed loop

① Settlement 7–45 days

Decision events come with label_ready_at. It takes 14 days for contamination, 21 days for rooting, and 45 days for transplant survival. At the end of the period, the final label will be backfilled by a scheduled task.

Before there is a final label, the sample is labeled pending, Not participating in training- This is the gate that prevents label noise from contaminating the calibration.

② Calibration weekly

0.05 triggers refitting.

③ Drift daily

Three levels: input drift (PSI/KL on sensor and image features), prediction drift (decision distribution), and result drift (contamination rate/survival rate). The first two are visible the same day, the third will have to wait 45 days.

④ Shadow ≥30 days

The new model runs in parallel with the new farm, only recording but not executing. Compare the consistency rate and disagreement sample distribution of AI and artificial intelligence, Disagreement is not a mistake, it is a message.

⑤ Promotion quarter

Threshold: Cost-weighted net income does not decrease And ECE does not rise And The review consistency rate does not decrease. If any of the three are not satisfied, it will not go online - even if the accuracy is higher.

active learning queue

Priority is given to labeling three types of samples: Review Area Disagreement (Both the model and the person hesitate), OOD hit、high confidence error. The amount of information for each 100 pieces of these three categories is approximately equal to 1,000 random pieces.

7.2 Calibration: Why 0.82 cannot be used directly The curved line on the reliability chart is the difference between "confidence" and "correctness"

ideal diagonal Uncalibrated (overconfidence) After calibration

Three actions, from low to high cost

  • temperature scaling (cheapest): p' = σ(logit(p)/T), a scalar parameter that barely changes the ranking, only the credibility scale.
  • Isotonic / binning calibration 2000); small samples are prone to overfitting.
  • Conformal abstention: Without correcting the probability, directly give "how big is the answer set of this sample". Collection contains ≥2 categories → waive upgrade. This is the only method with a limited sample guarantee.

In engineering, there are three superpositions: temperature scaling tube scale, conformal tube boundary, and OOD tube. "This set of scales is not applicable here at all."

Note: The threshold cannot be calculated by cost alone. The pure cost solution will give an answer of 4% "almost every plate is isolated" - there must be lower operating limit (the amount of false isolation that can be tolerated per week) brings it up, which is why τ_cost is shown separately from τ_hi in panel A.

9.3 How can the pilot be proven effective? Turn "Feeling Better" into a pre-registerable test

The 90-day roadmap delivers systems, not evidence. To get the boss or investor to sign, you need in advance Determine the design, sample size, end point and stop loss rules — A system that allows hindsight to pick indicators will always "work."

① Shadow comparison D60–D90 · 30 days

No operations are changed, only "AI suggestions vs agronomist judgments" are recorded. The output is judge quality evidence, not evidence of loss.

Main indicators: human-machine consistency rate, arbitration results of divergent samples. This step cannot be omitted - it can reveal that "the model and the master are not in the same channel at all" before burning money.

② Stratified randomized control D90–D180 · Two lots

press shelf Cluster randomization: Group A implements the AI recommendations, and Group B implements the current SOP. The same mother plant library, the same nutrient solution batch, and the same period control.

Main indicators: contamination rate, transplant survival rate. This is the only design that can support ROI.

Enable in full, while retaining Blind sampling of 20 high-confidence decisions per day,continuously monitor the silent error rate.

Without this step, the system will quietly deteriorate in a week that you don't notice, and you will only see a good-looking monthly report.

Stop loss rules (written into the contract, not verbal)

  • The contamination rate of the control group was 2 times higher than that of the experimental group for 3 consecutive weeks → Terminate control early and switch to full volume (You can’t continue to make people suffer for the sake of statistical efficacy)
  • Ledger disconnection, audit export failure → Immediately deactivate automatic disposal permissions, compliance takes precedence over effects
  • Review SLA achievement rate for two consecutive weeks
  • 2% → shrink the automatic processing range until the review consistency rate is restored

Mixing Control: Four Most Common Mistakes

  • Compare "last year vs this year"— The seasons, electricity prices, and varieties have all changed, and the conclusion is meaningless. Must be compared at the same time.
  • Randomly by single plate— Fog, temperature, and humidity on the same shelf are highly correlated, and randomly pressing the plate will leak the treatment effect to the control group. The unit of randomization shall be the shelf.
  • Exchange two things at the same time— While using the AI, I changed the nutrient solution formula, and in the end it couldn’t be attributed.
  • Use the human-computer consistency rate as an effect indicator— The agreement rate only means "like people", not "accurate than people".

Consistency rate trap: What if the AI is only 70% consistent with the master, but the AI is more accurate?

This is the most common deadlock during the shadow period. The correct approach is not to “put people first”; Third-party blind review arbitration: Shuffle the 200 divergent samples and give them to two people Unaware 60%, it means that it brings incremental information; if it is

This step does not cost thousands of dollars, but it can avoid two expensive mistakes: launching a model that no one believes in, or rejecting a model that is better than others.

10.1 Don’t make a list Written “don’ts” protect the project better than written “dos” on the roadmap

❌ No unsupervised valve control

decision layer output intention, the execution layer is constrained by the PLC hard limit, and the main switch is reserved. This rule does not change as the model becomes more accurate.

❌ No prescription for disease treatment

We only do "identification + isolation + recommendations for inspection". Specific dosage and application of pesticides/fungicides must be determined by a certified agronomist regarding MRLs and regulations.

❌ Does not replace cupping and quality grading

Sugar content, flavor, and defects are human sensory judgments; the decision layer can only do "harvest window sorting" and does not make final grade assessments.

❌ No automatic determination of the legality of variety rights

The system can mark "lack of authorization certificate" but cannot conclude that "this breed can be reproduced".

❌ Do not centralize raw data across farms

What is shared are features and parameters, not images and batch details. This not only protects customers, but also protects ourselves.

❌ Don’t make a “general agricultural model” first

We’ll talk about it after finishing the coffee single category. Multi-category expansion will spread the limited labeling budget into a net that no one can feed.

coffeejev/service/judgers.py (excerpt)
from math import exp, log def _logit(p: float) -> float: p = min(max(p, 1e-4), 1 - 1e-4) return log(p / (1 - p)) def _sigmoid(x: float) -> float: return 1.0 / (1.0 + exp(-x)) def judge_contamination(vision_p, quality, temp, rh, days_in_culture, batch_hist_rate, cost_fp=40.0, cost_fn=900.0, t=1.35): """Noul judger: three bands plus a cost-derived threshold. Returns (decision, p_cal, tau_hi, tau_lo).""" prior = min(max(batch_hist_rate, 1e-3), 0.5) blend = (quality * _logit(vision_p) # the sharper the image, the more the model is trusted + (1 - quality) * _logit(prior) # the blurrier, the more the prior + 0.35 * (temp - 24) / 3 # warmer runs favour contamination + 0.25 * (rh - 65) / 15 + 0.12 * (days_in_culture - 14) / 7) p_cal = _sigmoid(blend / t) # temperature scaling pulls the scale back to reality tau_cost = min(max(cost_fp / (cost_fp + cost_fn), 0.02), 0.5) # cost-derived tau_hi = min(max(tau_cost, tau_min), 0.5) # two-stage: raise it to the operating floor (CH-15) tau_lo = max(0.06, 0.45 * tau_hi) if p_cal >= tau_hi: decision = "isolate_and_sample" elif p_cal >= tau_lo: decision = "review_microscopy" else: decision = "continue" return decision, p_cal, tau_hi, tau_lo
