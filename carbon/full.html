01 / WHY NOW

计量出来的碳数可以审，表格里的碳数是猜的

metered primary data vs. spreadsheet estimate — the only durable difference

欧盟及主要买家的产品碳足迹要求，指向的是同一条工程约束：优先使用特定现场的一次数据（site-specific primary data），并披露二次数据占比。ISO 14067 与 PAS 2050 都不禁止估算，但要求把估算和实测分开记账、分开披露。绝大多数农产品的碳标签之所以无法通过深度核证，不是因为算错了，而是因为分母（产量）和分子（能耗）都来自事后汇总的表格，既没有时间戳，也无法证明没有被修改过。这是构造成本问题，不是态度问题：没有计量装置，一次数据在结构上就拿不到。

我们的机队恰好在两个最重的分项上有计量级来源。power-meter-PuEr-01 每 60 s 报 power_kw / kwh_total / tariff，是带累计寄存器的真实电能增量，而不是"功率 × 时长"的推算；fog-ctrl-A3 报 ec / ph / do / water_temp 与 fog_duty，配合加肥泵的配方记录，可以把氮投入量从"按采购单摊"变成"按实际配液批次累加"。这两项合起来占本页算例中一次数据占比 65.5%（0.1273 / 0.1943）。剩下 34.5% 是包装、外运、硬件摊销这类上游二次数据，行业里通常靠供应商因子表，属于可替换项，不构成结构性缺陷。

时间戳是第二层。碳排放的时间分辨率决定了因子该用哪一个：同一度电在 00–06 时段（0.31 kgCO2e/kWh）与 17–21 时段（0.58）之间差 87%。用年度平均因子算出来的数，会让"把补光与雾化移到夜间低谷"这类真实减排动作完全消失在账上——既奖励不了正确的行为，也识别不出错误的配置。本页的引擎按六段小时边际因子对每个计量区间逐段加权（见 §3），所以灯谱、轮作、峰谷电价策略的改动会直接反映到标签数字上。

第三层是哈希链。每个批次的碳账本在封账时对"区间清单 + 计量摘要 + 配方记录 + 产量"做规范化 JSON 的 SHA-256，并把上一批次的哈希写进本批次（prev_hash），形成只可追加、不可回改的批次链。核证方拿到的不是一份 PDF，而是可以独立重算的输入集：他能自己把 134.4 kWh 乘上因子表，得到 57.232，再看我们的 57.232 是否一致。能被别人重算，才叫可审计；其余的所谓"碳管理平台"，本质是把不可验证的估算换成不可验证的仪表盘。

path a · spreadsheet carbon

表格里的碳数 不可审

  • 分子：月度电费单 ÷ 出苗数，平均因子，时间分辨率 = 1 个月
  • 分母：出库单汇总，批次口径靠人工对账
  • 可追溯性：无原始序列；改了单元格无人知晓
  • 核证成本：核证方只能抽样访谈，结论只能是"合理保证"
  • 结果：一次数据占比 ≈ 0，标签在欧盟买方尽调中很难被采信
path b · metered carbon

计量出来的碳数 可复算

  • 分子：kwh_total 累计寄存器逐区间差分，60 s 粒度
  • 分母：批次 ID 绑定株数与封账时点，T+0 生成
  • 可追溯性：原始区间序列 + sha256 摘要 + prev_hash 链
  • 核证成本：核证方重算而非访谈，工作量从"查账"降为"跑一遍公式"
  • 结果：一次数据占比 65.5%，可对外披露二次数据占比，符合 14067 披露要求

所以"现在"不是指市场窗口，而是指数据条件刚刚成立：同一套遥测已经同时喂给闭环控制与碳账本，边际成本接近于零。如果先做标签再补计量，就要重建数据链路；而按现在的顺序——控制层 → 遥测 → 批次账本 → 标签与积分——每一层都复用下一层的输入。这也是本页唯一一个真正的差异化论点，其余部分（因子、标签、积分）都是可被同行复制的工程细节。

02 / BOUNDARY & FUNCTIONAL UNIT

边界与功能单位：纳入了什么，以及每一项排除的理由

cradle-to-gate · ISO 14067 / PAS 2050 aligned · GHG Protocol scopes

系统边界为 cradle-to-gate：从上游投入品生产、育苗车间运行，到苗出厂交付（门到门含外运）为止，不含种植端成株阶段、不含消费者使用、不含最终处置。 Scope 1 / 2 / 3 按 GHG Protocol 划分；排除项一律给出可审计的排除理由，而不是"暂不计入"。

03 / METHOD
与线上引擎的对照：本页的演算样例是 CJV-B-2026-0417（134.4 kWh，均值 0.4258）。 实际运行的引擎对批次 AP-0712 算出 0.1951 kgCO₂e/株（-53.5%，B 级）， 差异只来自电力均值口径与是否保留向上取整。两者都可复算 —— 以线上标签的哈希为准。

算法与因子：公式链、单批算例、小时曲线与不确定度

formula chain → worked example (480 plantlets) → hourly MEF → uncertainty

全部数值可复算：给定因子表和计量序列，任何第三方都应能算出一模一样的 57.232、3.888、96.00。这也是本方法学能被核证的唯一理由。

3.1 公式链 engine formula chain

# 1) 电网排放：逐区间加权，不用年度平均因子 E_grid,b = Σ ( ΔkWht × MEFt ) , ΔkWht = kwh_totalt − kwh_totalt−1 MEFt = band( local_hour(t) ) → { 00–06: 0.31 | 06–09: 0.38 | 09–12: 0.44 | 12–17: 0.47 | 17–21: 0.58 | 21–24: 0.41 } # 2) 其余分项：活动数据 × 因子 E_N = m_N × 13.5 // kg N × kgCO2e/kg N E_pack = n_out × 0.012 // 出库套数 E_trans= n_out × 0.020 // 常温干线；冷链 ×1.6 E_hw = A_hw × 8 dev / 4 yr / Q_year // 专用资产按年出苗量摊 E_computed = E_grid + E_N + E_pack + E_trans + E_hw E_unit = E_computed / n_batch E_declared = ceil(E_unit, 0.01) // 向上取整 = 保守方向 # 3) 避免量 → 积分 A_unit = 0.42 − E_declared // 基线 0.42（区间 0.34–0.52） P_batch = A_unit × n_batch × mult(grade) // 1 point = 1 kgCO2e avoided mult = { A: 1.0, B: 0.9, C: 0.8 } // 数据质量等级 Value = P × ¥0.10 // 仅可兑硬件/SaaS

取整方向是刻意的：向上取整使声明值永远不低于计算值，代价是 0.0057 kgCO2e/株（2.9%）的保守偏差。审计上"偏保守"可接受，"偏乐观"不可接受。

sensitivity · 负荷时移

把负荷挪到 00–06 段能省多少

六段因子的用途不是"算得更精细"，而是让时移可被计价。若补光与雾化全部压到 00–06 段（0.31）： 0.28 × 0.31 = 0.0868，电耗排放从 0.1192 降到 0.0868（−27.2%），单株总量 0.1943 → 0.1618，声明值 0.17，对基线减排 59.5%。

反向：若负荷集中在 17–21 段（0.58），单株电耗排放 0.1624，总量 0.2375，减排跌到 43.5%。同一套硬件、同一个产量，标签数字差 17 个百分点——这就是为什么要用小时因子而不是年度均值。

the dominant term · 真正的不确定度在这

基线的不确定度是产品排放的 4 倍

基线 0.42（区间 0.34–0.52，±0.09）是自声明的。合成到"避免量"上： √(0.0237² + 0.09²) = 0.0931，即 A = 0.22 ± 0.093 kgCO2e/株（±42%）。 传导到减排率：30%–75%；若只看基线区间、把实际值固定在 0.20，则为 41%–62%。

所以"52%"这个数里，真正脆弱的不是我们的 0.200，而是分母 0.42。任何对外声明都必须写成"相对本方法学定义的常规土壤育苗基线"，而不是"比传统方式少一半"。

precision vs accuracy

我们把精度花在了不重要的地方

计量到 60 s、因子分 6 段、声明到 0.001，这些提升的是精度（可复算、可比较、可审计）；而总结果受限于基线假设，提升不了准确度（离真值多远）。

这在方法学上是可接受的取舍，但必须在对外材料里说清：精确的账 + 粗糙的基线 = 一个精确的相对比较，不是一个绝对真值。内部控制上，基线区间单独维护、单独版本化，与标签哈希分开签名。

04 / CARBON LABEL

碳标签：字段、样张、JSON 结构，以及任何人如何验证它

4.4 验证流程：从 ID + 哈希到重算 public verification

verifier path · 任何人

五步，不需要我们的账号

  1. 扫码或输入 ID → 拿到标签记录。QR 内容只含 label_id + 哈希前 12 位，不含任何个人信息。
  2. 重算哈希 → 按公开的规范化规则对记录重算 SHA-256，与 hash 逐字节比对。不一致 = 页面或记录被改过。
  3. 重算排放 → 用记录里的 activity × factors：134.4 × 0.425833 = 57.232，再逐项求和得 93.280，ceil → 0.200。任一步不符即在页面标红。
  4. 校验链 → 用 prev_hash 回溯上一批次，直到链首（可离线校验，不需要全量数据）。断链即失效。
  5. 验证原始数据 → 请求 inputs_digest 对应的原始区间序列，用同一摘要算法核对。这一步需要数据方授权（核证方、买方尽调、监管），不是全公开。
design rules

四条硬约束

  • 哈希不可写回：封账后记录只读，修订必须出新版本（version+1）并保留旧版
  • 摘要粒度 ≤ 60 s：原始区间保留 24 个月，之后只保留摘要（存储与可验证性的平衡）
  • 因子版本化：factors 全部内嵌在记录里，不引用外部链接——否则五年后无法复算
  • 不依赖我们的域名：验证所需的一切都在记录与哈希里；页面只是入口，不是验证的前提

若把验证做成"必须登录我们的平台才能看"，那它就不是验证，是展示。

05 / POINTS ECONOMY

积分经济：三方账本，以及 24 万株/年的逐项算术

grower · platform · buyer — 1 point = 1 kgCO2e avoided = ¥0.10, redeemable only in-kind

¥4,752/年 的面值只有首年硬件支出的 6.1%。把积分当卖点是对农户的误导，它实质是一张"回头再买"的抵用券，成本落回我们自己身上（¥3,384）。真正的价值主张是溢价与合规通行证。

单场稳态毛利 ¥9,816/年。要覆盖销售、研发与核证体系，只能靠持续新增场次或把 SaaS 单价抬上去（¥0.03 → ¥0.10/株/年 即 ¥24,000/年）。这是商业模型的真实缺口，不是可以含糊过去的地方。

honest reading · 3

5.4 溢价通道的口径问题 premium caveat

溢价按绿果重量计价（¥0.3–1.0/kg），而我们的功能单位是苗（株）。两者之间缺一个成株阶段的产出系数（每株成株年产绿果 kg），该系数本页没有计量基线，因此 30 t 只作为情景参数出现，不得解读为 24 万株的必然产出。 正确的做法是：等后期阶段（FU 2）建立计量基线后，用同一套账本把"苗 → 绿果"的产出系数也变成可审计量，届时溢价才能与株数直接换算。在那之前，溢价只能按吨报价、按批结算。

另一个口径问题：溢价由谁支付、在哪个环节实现。若买方只认"整批绿果"而不认苗，则苗阶段的减排实际上是通过下游成株批次的碳标签变现的，中间的分配规则（按质量、按经济价值、还是按阶段独立核算）必须写进合同，否则出现 §6.7 的分配争议。本页立场：两阶段各自独立核算、独立签发标签，苗阶段不向成株阶段转移排放或权益。

06 / RISK & COMPLIANCE

风险与合规：12 条会让这套东西变成负债的路径

claims · double counting · baseline · MRV independence · data gaps · allocation · regulation

这一节不是免责声明，而是设计约束清单。每一条都给出"敞口"与"做法"，可直接转成合同条款、标签印刷规范与内部审计项。

01绝不称其为"碳信用 / carbon credit"

积分不是抵消额，不能用于买方宣称"中和"，不可转让、不可交易、无登记簿对接。一旦在文案、合同或销售话术中出现 credit / offset / 中和 / 净零，即构成对产品性质的错误陈述。

不可交易、不可抵消、仅限兑换我方产品；对外统一称"低碳积分 / low-carbon points"。合同、标签、SaaS 文案三处措辞须一致，季度审查。

02重复计算（double counting）

三类重复：① 同一批次被两个种植者申报；② 同一台设备的多场数据被计入两个批次；③ 苗阶段减排被成株阶段的买方再次声称为"自身减排"。第③类最隐蔽。

批次 ID 全局唯一且绑定设备序列号；一台设备在同一时段只能归属一个批次；在标签与合同里写明"本减排量已由上游环节声明，下游不得重复主张"。

03漂绿（greenwashing）表述

"−52%" 只在"相对本方法学定义的基线"下成立。写成"比传统种植少一半排放"、"环保苗"、"零碳苗"即越界；"碳中和"在无抵消机制的前提下完全不成立。

所有对外数字必须带三个限定词：口径（cradle-to-gate）、基线（0.42，区间 0.34–0.52）、版本（AR6 / 因子表版本）。缺一即不予批准发布。

04基线是自声明的

0.42（0.34–0.52）来自文献与行业访谈，不是同一区域、同一品种的对照实测。它贡献了避免量不确定度的绝大部分（±42%），却不在我们自己的计量范围内。

尽快建 2–3 个对照小区（常规土壤育苗，同品种同季节，记电、肥、基质、运输）；在拿到对照数据前，基线以区间而非单值对外，并在标签注明"baseline: self-declared, 0.34–0.52"。

05MRV 独立性

我们既是算法与账本的提供方，又想收核证费——这是结构性利益冲突。自证 + 自收费在买方尽调中会被直接质疑，并可能被认定为不具备核证资格。

核证须由第三方机构出具，平台只做数据准备；核证方拿只读镜像与私钥签名材料，不与业务团队同线汇报；平台留存 40% 服务费要能说清是数据处理费而非核证结论对价。

06数据缺口与回退估计

网关掉线、电表更换、批次跨月、传感器漂移都会造成区间缺失。回退用"估算"会把 A 级直接打成 C 级，且必须被披露——不能静默补齐。

缺失 <5%：按同设备前 7 日同时段中位数插补，标 grade B；>5% 或关键分项缺失：grade C，乘数 0.8，并在标签记录 estimation 字段写明方法与覆盖率。缺失 >20% 不予签发。

07苗阶段与绿果阶段的分配

两阶段共用设备与人员，若把苗阶段的排放全部推给苗、把收益全部留给绿果，或反之，都会扭曲标签。分配方法（质量/经济价值/独立核算）必须事前确定并披露。

本页口径：两阶段独立核算、独立签发，不做跨阶段分摊；共用设备按机时（kwh_total 归属）拆分到阶段，人员与厂房不摊（已声明排除）。改变分配方法须升版本号。

08中国监管语境：CCER 与碳普惠 待法务确认

全国温室气体自愿减排交易市场（CCER）走"方法学 → 登记 → 核证 → 交易"路径，须由备案的方法学与审定/核证机构支撑；碳普惠则多为地方/消费端自愿减排机制，通常不能进入全国碳市场，多用于兑换与激励。

本机制既非 CCER 项目、也非任何已备案的碳普惠项目，是产品碳足迹标签 + 企业自有积分。公开材料中不得出现"减排量可交易""可抵销""纳入碳市场"等表述；是否需在地方碳普惠体系下备案，须法务与主管部门确认。咖啡育苗/气雾栽培目前未见公开方法学，不得假定可开发。

09电力因子的口径漂移

边际/平均、省级/区域电网、小时/年度、是否含绿电交易，四种口径混用会让同一度电的排放差 2–3 倍。绿电证书（如有）能否抵扣、如何避免与电网因子双重扣减，也需明确。

标签内嵌完整因子表与版本号；GHG Protocol Scope 2 双报告（location-based / market-based）两者分开披露；若采购绿电，须扣减并保留凭证摘要，避免既用绿电又用全国平均因子。

10计量边界漂移与多租户归属

设备增删、棚室改造、同一网关服务多个种植者、批次跨场并批，都会让"这台表为这个批次供能"的假设失效。边界一变，历史数据就不可比。

设备-棚室-批次三层绑定写入注册表（复用 /api/overview 的实体）；变更须走变更单并切分批次；跨场并批一律拆账，不做合并签发。

11积分会计与消费权益

积分是负债不是收入；兑换率、有效期、作废规则若在条款中不清，可能构成对消费者的不利条款（农户作为经营者适用不同规则，需分别设计）。

积分台账逐条留痕（签发/兑付/作废/调整）；条款明示有效期与变更权；兑换率调整只能对未签发的批次生效；计提按期望兑付率，季末重估。

12生物源碳的错误主张

苗在生长中吸收 CO2，但按 ISO 14067 不计入产品碳足迹，也不得用于冲抵排放。把它写成"固碳"或"负碳"是最常见也最容易被一眼否掉的主张。

边界内明确写"生物源碳不计入、不可冲抵"；任何提到固碳的材料须同时说明"短期生物碳储不构成永久移除，且不在本标签核算范围内"。
