## 3. 三个核心设计主张

1. **阈值是成本结构的函数，不是常数。** `τ_cost = C_FP/(C_FP+C_FN)`，再与运营下限取大 `τ_hi = max(τ_cost, τ_min)`。纯成本解会给出 4.3% 这种「几乎每盘都隔离」的答案——现场执行不了，这一层必须被显式建模（页面 04 面板可拖）。
2. **置信度必须校准，且要能弃权。** softmax 的 0.82 常常对应 0.55 的真实正确率。温度缩放管刻度、conformal 管边界、OOD 管「这套刻度这里不适用」。
3. **「不决策」是合法输出。** `need_more_info` / `abstain` / `stop_and_review` / `defer_to_human` 四种不决策，比逼模型给一个答案更省钱——这是判断层和聊天机器人的分界线。

## v1.0.1 修订（2026-11-01 评审后）

对页面引擎、Python 参考实现与文档做了 6 处行为修正（测试 33 → 41，全绿）：

| # | 问题 | 修正 |
|---|---|---|
| 1 | `review_microscopy` 返回 `human_review=false`——「叫人来镜检」却没人被叫，复核队列收不到最贵的样本 | 决策非 `continue` 即强制 `human_review=true`，带 `boundary_zone` 理由 |
| 2 | 状态全部达标时 Choice 仍建议「停雾降湿」；根因是 SOP 基线挂 0.30 成本、dry_back 只挂 0.12，最便宜的任意动作总赢 | `cost_index` 改为**边际成本**（维持=0）；达标态唯一正确答案是 `sop_baseline` |
| 3 | Choice 置信度取 softmax 最大值，六个近似打平的候选里只有 ~0.2 → 每个正常批次都进复核，与 <15% 复核率冲突 | 改为边际置信 `σ(ΔU/τ)`，τ=0.01；约束压成单选时 0.88，高成本单选（≥0.20）追加 `value_threshold` 复核 |
| 4 | 液温 >24°C 被当成每个选项的违规 → 6 个候选同时「不可行」，输出「请确认探头是否失效」，真实原因是冷水机 | 液温改为**前置闸门**（zone gate）：`stop_and_review` + `scores.zone_gates` 指名原因，选项表仍排序供冷却后参考 |
| 5 | readiness 的「株高/根数比」`ratio/0.6*100` 让徒长苗拿满分、根数 0 也满分；`completeness` 写死 1，缺 6 个读数仍报 0.80 置信度 | 比值改目标带 0.35–0.65（两侧扣分）；完整度由调用方按真实提供的证据计算 |
| 6 | 所有 stage 都要求 `sensors.ec/ph/vpd/temp`——组培瓶里没有 EC/pH 探头，真实的无菌检查请求被误判 `need_more_info` | 必填字段按判断器区分（contamination 只要 temp；readiness 要求至少一个形态学读数） |

文档同步修正：§6.2 RV-2412 示例数字自洽、§6.3 哈希算法如实标注 FNV-1a（非 SHA-256）、
附录 Python 片段补 τ_min 两段式并对齐 ROUTES、stage 枚举对齐 14 节点、`review_reason`
