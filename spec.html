01 / DESIGN REVIEW

设计评审：v0.1 的判断是对的，工程还差一层

先把「判断层」这个定位钉死，再补上让它跑得起来的四条腿

评审用四个维度切入：可判定性（输入够不够判）、可执行性（判完能不能落地）、可学习性（落地后能不能变强）、可交付性（上线能不能撑住）。v0.1 在「可判定性」上完成度最高，缺口集中在后三项。

1.2 十二条缺口 按「不补会怎样」排序，不按好看程度排序

G01

只有 stage，没有批次谱系

可执行性
草案里 stage 是个字符串，但污染一旦发生，真正要回答的是「隔离哪些盘、受影响几层架、哪批母株要停用」。没有 batch_id → 母株 → 托盘 → 架层 → 雾培槽 的谱系图，隔离半径算不出来，只能整温室停摆——这是雾培最贵的失败模式。
谱系图 + 污染事件沿图做 BFS 得隔离半径；把 blast_radius 作为独立候选动作进入 Choice（隔离多少盘本身就是一个决策）。
G02

置信度没有定义，也没有校准

可交付性
草案示例里 confidence: 0.82 直接来自模型 softmax。视觉模型在训练分布外普遍过度自信（深度网络 ECE 常在 0.1–0.2），于是 0.82 可能对应真实 0.55 的正确率。用它做阈值，等于用一个没有刻度的仪表盘做手术。
校准层（temperature scaling / isotonic）+ ECE 与可靠性图上线监控 + 弃权机制（conformal 预测集：会输出两个候选项时直接升级）。
G03

「污染」二元判定太粗，判对了也可能做错

可判定性
细菌性、真菌性、玻璃化、螨害、病毒，行动完全不同：细菌→整盘销毁 + 台面消杀；真菌→隔离 + 降湿 + 换气；玻璃化→降激素 + 增换气；螨→全层处理。二元输出把五种处置压成一个 true，下游只能靠人的记忆补全。
Noul 扩为 5+1 类（5 病类 + 1 非生物胁迫），并输出时间维度（首次可见 → 不可逆的剩余天数），动作模板随类别自动绑定。
G04

标签是延迟到达的，管线里没有位置放它

可学习性
污染标签 7–14 天到，移栽成活 30–45 天到。草案说「用成活率回流」，但没有任何组件承接「今天做决策、下个月才知道对错」。结果必然是拿代理标签凑，校准随季节漂移。
延迟标签表（决策事件 + label_ready_at + 回填任务）+ 双轨标签：训练用终局标签，监控用代理标签。
G05

传感器本身不可信，但没有质量闸门

可交付性
EC/pH 探头一两周就被生物膜糊住；pH 电极在低离子强度营养雾里漂移更快；摄像头进雾结露。一套「相信一切输入」的判断层，会在探头坏掉的那周给出非常自信的错决策。
感知层加 sensor_health（漂移率 / 响应时间 / 双探头交叉校验 / 更换周期），任一 <0.6 → 决策降级为 need_more_info 或弃权，绝不静默使用。
G06

「建议调整营养雾」落不到阀门上

可执行性
草案边界写得很对（关键动作人工确认），但没有执行侧的机械设计：指令发出后没人确认执行、执行了没人回读、回读偏了没人回滚。于是「决策」和「现场」永远差一步，归因也就断了。
指令 → 网关 ACK → 30s 后回读实测 → 偏差超限则回滚 + 告警；硬限位（EC/pH/压力/雾化占空比）下沉到 PLC，软件层不可越过。
G07

没有黄金集与回放，改阈值就是赌博

可学习性
阈值从 0.7 调到 0.6，是变好还是变坏？没有历史回放和成本加权混淆矩阵，只能靠「感觉最近污染少了」。这类项目最常见的死法就是无法证明自己在变好。
决策回放（历史传感器 + 图像重跑）+ 成本加权损失 + 影子模式；晋级门槛：净收益不降 且 ECE 不升。
G08

human_review 是个布尔，没有落地的地方

可执行性
标记为 true 之后呢？谁看、多久内看完、不同意的怎么记？没有队列和理由分类，复核数据等于扔掉——而这恰恰是最贵的标签。
复核队列 + 4 类理由（图像不可判 / 超 SOP / 首次场景 / 高价值批次）+ 采纳·改判二值记录 → 直接进训练集。
G09

objective 有权重，但没有成本函数

可交付性
气雾栽培最大的变动成本是电（雾化泵、除湿、补光、水冷）。只优化成活率的 Choice 会收敛到荒谬解：永远开雾、EC 拉到上限。草案的 {survival, cost, quality} 权重有了，但没有东西去度量 cost。
每个候选动作携带 (kWh, 水 L, 营养盐 g, 人工 min) 成本向量；Choice 输出帕累托前沿而非单一标量，由业务场景选点（合约品质 vs 大宗量产）。
G10

新农场/新品种没有冷启动方案

可学习性
草案说「按品种/产区建基线」，但没说怎么建。为每个农场单独训练模型，在只有几批数据的农场里必然过拟合；而一个全球模型又会抹掉产区差异。
层次化部分池化：品种级共享先验 + 农场级偏移（少量样本即可估）；OOD 检测（特征距离 / 能量分数）；新场景强制影子运行 30 天再放开。
G11

合规、审计与数据主权没进架构

可交付性
组培材料牵涉品种权与植物检疫；跨境部署牵涉数据本地化；营养液排放有法规限值。而「这批苗当时为什么被判为可移栽」将来是要拿得出证据的。
追加式哈希链决策账本（决策 + 输入快照哈希 + model_id + SOP 版本）+ 数据分级（原始图像不出境，仅出梯度/统计量）。
G12

0.7 / 80 / 60 这些阈值没有来源

可判定性
「置信度<0.7 升级」「≥80 可移栽」是拍出来的。同样的 0.7，在幼芽期和移栽前意味着完全不同的损失。阈值应该是成本结构的函数，不是常数。
阈值 = 成本比 τ_cost = C_FP /(C_FP + C_FN)，再与运营下限取大 τ_hi = max(τ_cost, τ_min)——否则纯成本解会退化成「几乎全部隔离」；三区间（处置 / 复核 / 放行）替代二元；用决策曲线分析看净收益。

1.3 三处必须修正的技术判断 不是补充，是方向性纠偏

C1 「低置信度才升级」这个规则本身有漏洞 高

只按置信度抽样，会系统性漏掉高置信度的错误——那才是真正贵的错误：模型对一整类新出现的螨害很确信地判成「健康」。

修正：升级策略必须加入与置信度正交的三个维度 —— OOD 分数、每日随机盲复核（抽 20 条高置信度决策）、分品类精度告警。要监控的是静默错误率，不是平均置信度。

C2 「<300ms」不能作为全系统 SLA 中

端侧图像判断可以 300ms 内；但一次营养雾 Choice 要融合时序、成本、约束与多目标，云端 p95 就是 1.5–2s；专家复核是小时级。用一个数字承诺全链路，第一次演示就会失信。

修正：分三级 SLA —— 端侧快判 ≤300ms（p95）、云端集成 ≤2s（p95）、专家升级 ≤24h（SLA 而非时延）。每级独立监控、独立告警。

C3 「2000 张图像」不足以训练污染判断 高

污染是稀有事件（3–8%），2000 张里只有 60–160 个正例，分到 5 个病类后每类十几张——连验证集都撑不住，更别说校准。

修正：5–8k 图像起步 + 主动学习挑边界样本 + 雾/结露/反光的合成增强 + LIMS 记录做弱监督（「该盘被销毁」也是标签）；顺序上先影子运行 30 天再谈上线。

保留清单（v0.1 里不该动的东西）

① 不做聊天机器人、只做判断层——这个取舍是整个设计里最值钱的一句话。② Noul / Choice / Score 三分法——足够表达 90% 的农艺决策，且天然可校验。③ 结构化 JSON 契约——让判断层能被编排、被回放、被审计。④ 「关键动作保留人工闸门」——在生物制造场景里，这不是保守，是产品竞争力。

02 / FULL-STACK ARCHITECTURE

七层全栈：快路径、慢路径、一条账本

感知 → 边缘 → 骨干 → 判断 → 编排 → 执行 → 学习，外加三条横切能力

草案的六层是对的，但把「执行」和「反馈」放在了同一个括号里。真实系统里这是两条不同的物理链路：一条要在 300ms 内落到泵阀上并回读验证，另一条要等 30–45 天标签到齐才能启动。把它们分开设计，是这套架构和草案最大的结构差异。

2.4 三种部署拓扑 同一个判断层，三种交付形态

T1 单农场 MVP

边缘盒子 ×2（主备）+ 农场本地服务器（MinIO + Timescale + 编排）。云只在模型分发时出现，推理与决策全部本地。

代价：无跨场学习；收益：断网可运行 72h、数据零出境、部署一天完成。

T2 区域多农场 规模化

农场保留采集与快判；区域云承担集成判断、跨场谱系（同一母株库供苗）与集中复核队列。图像留场，特征与决策上云。

代价：区域云运维；收益：新农场靠共享先验冷启动，复核人力集中。

T3 跨境联邦 出口

数据分级：L0 原始图像（不出境）、L1 特征向量（可出境）、L2 模型参数（受管）。联邦聚合只搬 L1/L2，本地模型注册表各自晋级。

代价：工程复杂度；收益：满足数据主权与品种权审查，同时共享全球经验。

三条横切能力（每一层都要有，不是某一层的活）

  • 安全互锁：EC/pH/压力/占空比的硬限位在 PLC，软件层只发意图；任何越界指令在网关侧直接拒绝并记事件。
  • 可观测性：每个决策带 trace_id，贯穿采集→推理→策略→执行→复核；指标按「判断器 × 品种 × 农场」切片。
  • 可审计：决策、输入快照哈希、模型版本、SOP 版本、复核结果全部入链；账本只追加，导出即凭证。

3.1 为什么这三处标星 驯化 readiness 是整条链的「汇率」

⑥ 驯化 readiness 衔接

它是组培与雾培之间的唯一汇率：定得太松，雾培端承担高死亡率；定得太紧，组培端压货、成本堆在瓶里。这个阈值会同时改变两条产线的经济性，所以必须由下游成活率反标定，而不是由组培车间自己定。

⑦ 移栽闸门 不可逆

出瓶是不可逆操作：污染一旦带进雾培槽，就是整槽风险。所以这里默认 human_review=true，AI 只负责「建议 + 排序 + 挑出不该移的」，不负责放行。首次移栽的新品种一律强制人工。

⑧ 营养雾配方 高频

一天可能触发几十次，是最适合「快判」的节点，也是最容易出事故的节点（EC 拉高 20 分钟就能烧根尖）。设计要点：硬限位在 PLC、软件只发意图，且每次调整必须能回滚。

3.2 状态机的四个迁移闸门 「当前在哪一阶段」本身就是一个需要判断的问题

迁移放行条件（全部满足）回退条件（任一触发）

5.2 响应字段与状态语义

响应头等字段

  • decision — 单值枚举，不含自然语言
  • confidence — 校准后置信度（见 7.2），不是 softmax 原值
  • scores — 判断器内部关键量（p、τ、readiness、utility…），用于事后归因
  • options[] — 候选动作、可行性、效用、概率
  • human_review + review_reasons[] — 布尔之外还要说为什么
  • reason — ≤80 字，只解释不看数据的人为什么该信/该疑
  • evidence_refs[] — 图像/传感器快照哈希，支撑可追溯
  • audit_id — 哈希链账本索引，出问题能回放

四种「不决策」也是正式输出

  • need_more_info — 字段缺失或传感器 health 不足。200 返回，不是 400
  • abstain — 校准后仍在复核区且无法补证（conformal 集含两个以上类别）
  • stop_and_review — 所有候选动作都违反硬约束，不允许系统自己选
  • defer_to_human — 首次场景/新品种/高价值批次，按策略强制

把「不决策」做成合法输出，比逼模型给一个答案更省钱——这是判断层和聊天机器人的分界线。

06 / HUMAN-IN-THE-LOOP

人工复核：把人放在正确的价位上，不是放在每个环节

升级策略是一张表，不是一个 if；复核结果是最贵的训练标签

07 / LEARNING LOOP

学习闭环：标签晚到 45 天，那就把闭环设计成异步的

延迟标签 → 校准 → 漂移 → 影子 → 晋级，五步各自有独立的时间尺度

这是草案里最容易被跳过、也最容易让系统在半年后失效的一节。核心思想：不要试图让模型「实时学习」，而是让每一个判断都留下可结算的凭证，等标签到齐后批量结算。

7.1 五步闭环

① 结算 7–45 天

决策事件自带 label_ready_at。污染 14 天、生根 21 天、移栽成活 45 天，到期由定时任务回填终局标签。

没有终局标签之前，样本标记为 pending，不参与训练——这是防止标签噪声污染校准的闸门。

② 校准 每周

在验证集上拟合温度参数 T（每「农场 × 品种 × 判断器」一套），监控 ECE 与可靠性图。ECE > 0.05 触发重新拟合。

③ 漂移 每日

三个层次：输入漂移（PSI/KL 于传感器与图像特征）、预测漂移（决策分布）、结果漂移（污染率/成活率）。前两个当天可见，第三个要等 45 天。

④ 影子 ≥30 天

新模型与新农场并行跑，只记录不执行。对比 AI 与人工的一致率、分歧样本分布，分歧不是错误，是信息。

⑤ 晋级 季度

门槛：成本加权净收益不降 且 ECE 不升 且 复核一致率不降。三者任一不满足，不上线——哪怕准确率更高。

主动学习队列

优先标注三类样本：复核区分歧（模型与人都犹豫）、OOD 命中、高置信度错误。这三类每 100 条的信息量约等于随机 1000 条。

7.2 校准：为什么 0.82 不能直接用 可靠性图上的那条弯线，就是「自信」和「正确」的差

理想对角线 未校准（过度自信） 校准后

三个动作，按成本从低到高

  • 温度缩放（最便宜）：p' = σ(logit(p)/T)，一个标量参数，几乎不改变排序，只改变可信度刻度。
  • Isotonic / 分箱校准：非参数，适合样本量大（>2000）的单判断器；小样本容易过拟合。
  • Conformal 弃权：不校概率，直接给「这个样本的答案集合有多大」。集合含 ≥2 个类别 → 弃权升级。这是唯一有有限样本保证的方法。

工程上三者叠加：温度缩放管刻度，conformal 管边界，OOD 管「这套刻度在这里根本不适用」。

注意：阈值不能只由成本算。纯成本解会给出 4% 这种「几乎每盘都隔离」的答案——必须有运营下限（每周可承受的误隔离量）把它抬起来，这也是 A 面板里 τ_cost 与 τ_hi 分开显示的原因。

90 天：先做三个判断器，但顺序反过来

草案说「先做三个判断器」是对的；但第一个月应该做账本和标签管线，而不是模型

理由是：模型可以在第 3 个月迭代很多次，但标签管线一旦前 60 天没建好，那 60 天的数据就永久废掉了。先建管道，再建模型，是唯一不能压缩的顺序。

9.1 三道验收闸门 每道闸门不过，就不进下一段

D30 · 数据闸门

  • ≥30 天连续传感器日志，缺失率 <2%
  • 决策账本上线，链验证通过率 100%
  • 延迟标签表有 ≥10 条已结算样本（走通全流程）
  • 相机标定与雾/结露质量指标上线

不过关的表现：账本里只有决策没有结果 → 说明标签回填链路是断的。

D60 · 模型闸门

  • 污染 Noul 在留出集上 FN 率 <8%（成本加权）
  • ECE ≤0.08；conformal 弃权率 <25%
  • 驯化 Score 的排序能力：与人工评分的 Spearman ρ >0.7
  • 营养雾 Choice 的候选集覆盖率 100%（总有一个可行解）

D90 · 上线闸门

  • 影子期 30 天，人机一致率 ≥0.85
  • 复核队列 SLA 达成率 ≥90%
  • 端侧 p95 ≤300ms，断网 72h 可运行
  • 成本加权净收益 ≥0（在影子数据上回放）

四道全过才允许把 mode 从 shadow 切到 live。

9.2 全球本地化 一个模型不能同时懂云南和哥伦比亚

本地化维度具体做法常见坑
品种 / 品系品种级共享先验 + 品系级偏移；Caturra / Geisha / 杂交种分别建基线用阿拉比卡整体均值代替品系，导致小粒种被系统性低估

电力与成本分时电价进入 Choice 成本向量；缺电地区降低雾化频率并接受产量折损成本模型不本地化，推荐的方案在当地根本付不起电费
法规与检疫种苗跨境需检疫证书；营养液排放氮磷限值；农药 MRL 按目的国把「技术上可行」当成「法律上可交付」
数据主权原始图像留境；跨境只传特征与模型参数（T3 拓扑）为省事把所有图像传回总部，出口时被卡

9.3 试点怎么证明有效 把「感觉变好了」变成一个可预注册的检验

90 天路线图交付的是系统，不是证据。要让老板或投资人签字，需要事先定好设计、样本量、终点与止损规则—— 允许事后挑指标的系统，永远「有效」。

① 影子比对 D60–D90 · 30 天

不改动任何操作，只记录「AI 建议 vs 农艺师判断」。产出的是判断质量证据，不是损失证据。

主指标：人机一致率、分歧样本仲裁结果。这一步不能省——它能在烧钱之前暴露「模型和老师傅根本不在一个频道」。

② 分层随机对照 D90–D180 · 两个批次

按架层整群随机：A 组执行 AI 建议，B 组执行现行 SOP。同一母株库、同一营养液批次、同期对照。

主指标：污染率、移栽成活率。这是唯一能支撑 ROI 的设计。

③ 常态化 D180+

全量启用，同时保留每日 20 条高置信度决策的盲抽样，持续监控静默错误率。

没有这一步，系统会在某个你没注意的周里悄悄变差，而你只会看到一张好看的月度报表。

终点基线 → 目标每组独立样本整群随机（设计效应 1.5）周期与说明
污染率8% → 4%≈ 550 盘≈ 830 盘按 14 天/批，约 3 批可攒够；这是最贵也最值得测的终点
移栽成活率72% → 80%≈ 450 株≈ 680 株需等 45 天观察期；建议与污染率同期启动，省一个季度
单次决策成本查账即可——不需要统计检验，账本里逐笔可核

n = (zα/2·√(2p̄q̄) + zβ·√(p₁q₁+p₂q₂))² / (p₁−p₂)² ，α=0.05 双侧，power=0.8

止损规则（写进合同，不留在口头）

  • 对照组污染率连续 3 周高于实验组 2 倍 → 提前终止对照，全量切换（不能为了统计功效继续让人吃亏）
  • 账本断链、审计导出失败 → 立即停用自动处置权限，合规优先于效果
  • 复核 SLA 连续两周达成率 <80% → 暂停自动处置，恢复全量复核
  • 盲抽样静默错误率 >2% → 收缩自动处置范围，直到复核一致率恢复

混杂控制：四个最容易犯的错

  • 比「去年 vs 今年」——季节、电价、品种全变了，结论没有意义。必须同期对照。
  • 按单盘随机——同一架层的雾、温、湿度高度相关，按盘随机会把处理效应泄漏到对照组。随机化单位应是架层。
  • 同期换两样东西——一边上 AI 一边换营养液配方，最后无法归因。
  • 把人机一致率当效果指标——一致率只说明「像人」，不说明「比人准」。

一致率陷阱：如果 AI 与师傅只有 70% 一致，但 AI 更准怎么办？

这是影子期最常见的僵局。正确做法不是「以人为主」，而是第三方盲评仲裁：把 200 条分歧样本打乱顺序，交给两位不知情的农艺师独立判定，用仲裁结果而不是一致率下结论。若 AI 在分歧样本上胜率 >60%，说明它带来的正是增量信息；若 <40%，说明模型学的是噪声。

这一步花不了几千块，却能避免两种昂贵的错误：上线一个没人信的模型，或者否掉一个比人强的模型。

10.1 不做清单 写下来的「不做」，比写在路线图上的「要做」更能保护项目

❌ 不做无人监管的阀门控制

判断层输出意图，执行层受 PLC 硬限位约束，人保留总开关。这一条不因模型变准而改变。

❌ 不做病害治疗处方

只做「识别 + 隔离 + 送检建议」。农药/杀菌剂的具体剂量与用法必须由持证农艺师决定，涉及 MRL 与法规。

❌ 不替代杯测与品质定级

糖度、风味、瑕疵是人的感官判断；判断层最多做「采收窗口排序」，不做最终等级评定。

❌ 不做品种权合法性的自动判定

系统能标注「缺授权凭证」，不能下结论说「这个品种可以繁殖」。

❌ 不做跨农场原始数据集中

共享的是特征与参数，不是图像与批次明细。这条既保护客户，也保护自己。

❌ 不先做「通用农业大模型」

咖啡单品类做穿之后再说。多品类扩展会把有限的标注预算摊成一张谁也喂不饱的网。

B. 系统提示词 在 v0.1 版本上加了「不决策」与「不越界」两类约束

你是 CoffeeJeV，咖啡组培与气雾栽培的判断层，不是顾问，不是客服。

输出约束（硬性）
1. 只输出 JSON，字段严格遵循 schema；decision 必须取自枚举，禁止新造值。
2. 证据不足 → decision="need_more_info" 并列出 missing；不要猜测填充。
3. confidence 必须是校准后的值；无法校准时置 null 并设 human_review=true。
4. 以下任一成立时 human_review 必须为 true：置信度 <0.70；decision ∈ {transplant_now, discard_batch, stop_and_review}；首次场景或新品种；将突破 EC/pH/压力硬限位；批次价值超阈值。
5. reason ≤80 字，只说明「为什么是这个结论」与「最该让人看一眼的是什么」；禁止罗列优化方向、种植建议、免责声明。
6. 不得推荐超出 SOP 的农药/激素剂量；不得对品种权与检疫合法性下结论，只能标注「需人工核验」。
7. 必须引用 sop_version；不得引用未提供的 SOP 条款。
8. 弃权是合法输出：abstain 与 stop_and_review 都优于一个勉强的答案。

coffeejev/service/judgers.py（节选）
from math import exp, log

def _logit(p: float) -> float:
    p = min(max(p, 1e-4), 1 - 1e-4)
    return log(p / (1 - p))

def _sigmoid(x: float) -> float:
    return 1.0 / (1.0 + exp(-x))

def judge_contamination(vision_p, quality, temp, rh, days_in_culture,
                        batch_hist_rate, cost_fp=40.0, cost_fn=900.0, t=1.35):
    """Noul 判断器：三区间 + 成本推导阈值。返回 (decision, p_cal, tau_hi, tau_lo)。"""
    prior = min(max(batch_hist_rate, 1e-3), 0.5)
    blend = (quality * _logit(vision_p)                # 图像越清晰，越信模型
             + (1 - quality) * _logit(prior)           # 图像越糊，越信先验
             + 0.35 * (temp - 24) / 3                  # 温度偏高 = 污染友好
             + 0.25 * (rh - 65) / 15
             + 0.12 * (days_in_culture - 14) / 7)

    p_cal = _sigmoid(blend / t)                        # 温度缩放：把刻度拉回现实
    tau_cost = min(max(cost_fp / (cost_fp + cost_fn), 0.02), 0.5)  # 成本推导
    tau_hi = min(max(tau_cost, tau_min), 0.5)      # 两段式：再与运营下限取大（CH-15）
    tau_lo = max(0.06, 0.45 * tau_hi)

    if p_cal >= tau_hi:
        decision = "isolate_and_sample"
    elif p_cal >= tau_lo:
        decision = "review_microscopy"
    else:
        decision = "continue"
    return decision, p_cal, tau_hi, tau_lo

ROUTES = {                      # 与 14 节点 stage 枚举一一对应
    "intake":                "contamination",

    "proliferation":         "contamination",

    "aeroponics_nutrition":  "fog_choice",
    "harvest_window":        "fog_choice",
}

def decide(req: dict) -> dict:
    missing = validate(req)                     # variety / region / stage / sensors.*
    if missing:
        return {"decision": "need_more_info", "missing": missing,
                "human_review": True}           # 200，不是 400：这是合法输出

    judger = ROUTES[req["stage"]]
    verdict = JUDGERS[judger](req)

    reasons = review_policy(verdict)            # 见 6.1 的矩阵
    verdict["human_review"] = bool(reasons)
    verdict["review_reasons"] = reasons
    verdict["audit_id"] = ledger.append(verdict)  # 哈希链，只追加
    return verdict
