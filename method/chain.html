02

RULE CHAIN / 口径链

口径链 12 条

每条规则给出编号、判据和可挑战点。判据必须落到公式或阈值；挑战点必须指向可争议的输入或常数，而不是态度。

判据 = 可执行公式 / 阈值 挑战点 = 可被反例推翻的假设
MTH-01决策阈值

成本不对称阈值

Cost-asymmetric threshold

用两类错误的相对成本决定拦截概率，不先验设定“污染率”。

判据
τ_cost = C_FP / (C_FP + C_FN) p ≥ τ_cost → 拦截侧；p < τ_cost → 放行侧

C_FP = 一次误放行的期望成本；C_FN = 一次误隔离的期望成本；p = 污染后验概率。

可挑战点两个成本由谁定价、如何核价；若成本来自客户合同，阈值必须随合同附件重算并进入版本记录。

MTH-02运营约束

运营下限

Operational floor

运营下限只允许抬高拦截概率，不允许被模型单独下调。

判据
τ_hi = max(τ_cost, τ_min) τ_min = 0.15 // 默认值

任何低于默认值的 τ_min 必须由合同附件单独列明，并写入决策记录的 method_version 与标签元数据。

可挑战点下限是业务约束，不是统计结论；客户可替换，但必须写进合同，否则不得用于签发。

MTH-03取证区间

双阈值取证

Two-threshold evidence

高阈值直接隔离，低阈值以上必须镜检复核，避免把不确定样本直接放行。

判据
τ_lo = max(0.06, 0.45 · τ_hi)
p 区间动作记录要求
p < τ_lo放行 / release常规决策记录
τ_lo ≤ p < τ_hi镜检复核 / microscopy review复核结论回写；未回写不得关闭
p ≥ τ_hi隔离处置 / quarantine隔离批次号 + 处置凭证

可挑战点0.06 与 0.45 是工程常数，不是从数据估计出来的；换作物或换复核成本后必须重新验证。

MTH-04硬闸门

硬闸门压分

Hard-gate score cap

加权分只负责闸门之上的排序，不能覆盖硬约束。

判据
cap = 100 if N_root < 3: cap = min(cap, 55) if browning > 60%: cap = min(cap, 60) if p ≥ 0.5: cap = min(cap, 40) S_final = min(S_weighted, cap)
触发条件分数上限
根数 N_root < 3≤ 55
褐变 browning > 60%≤ 60
污染后验 p ≥ 0.5≤ 40

可挑战点三个 cap 来自事故复盘；多个闸门同时触发时只取最小值，是否足以覆盖交叉风险，需要用反例检验。

MTH-05输出语义

弃权语义

Abstention semantics

弃权是正式输出，不是错误码；必须写入 ledger 并计入统计，不得用默认动作填充。

判据
precedence: need_more_info ≻ abstain ≻ no_safe_option ≻ defer_to_human ≻ decision
输出触发条件下游动作
need_more_info12 字段缺失或互相冲突指定补件字段与截止时间
abstain输入超出训练分布，或置信区间跨阈值不给出方向，转人工
no_safe_option可行集为空输出该语义；流程置 stop_and_review
defer_to_human成本参数未确认，或超出授权交有权限的人签署

可挑战点no_safe_option 与 defer_to_human 的边界由判定树固定；判定树变化必须发版。

MTH-06可行集

可行性先于效用

Feasibility before utility

先过硬约束，再算效用，最后只在可行集内排序；不允许用高收益补偿违规动作。

判据
F = { a ∈ A | g_k(a) ≤ 0, ∀k = 1..K } if F = ∅ → no_safe_option + stop_and_review P(a) = exp(β · U(a)) / Σ exp(β · U(a')), a, a' ∈ F β = 6 a* = argmax P(a), a ∈ F

g_k 为硬约束函数；U 为期望效用；β=6 是排序锐度，仅在可行集内生效。

可挑战点硬约束集合 K 是否完整，以及 β=6 在成本尺度变化后是否需要重标定。

MTH-07证据冻结

哈希链冻结

Hash-chain freeze

决策与标签同构，任何字段变化都必须导致哈希变化；旧记录不可覆盖。

判据
h_i = fnv(prev_hash ‖ canonical(payload_i)) canonical: key 字典序 · UTF-8 · 无冗余空白 · 十进制数字

payload 骨架含 method_version、inputs_digest、output、decided_at；标签使用同一骨架，可独立重算。

可挑战点FNV-1a-64 只提供篡改检测，不是抗碰撞承诺；外部锚定由客户另行决定；规范化实现变化必须升 MAJOR 并启新链。

MTH-08碳足迹

小时级边际因子

Hourly marginal factor

只用计量电能，不用估算电量；标签保留小时级电量与因子版本。

判据
E_batch = Σ kWh_h · EF(h) h = 1..24 label = E_batch / yield_kg [kgCO2e/kg]

MTH-09数据品质

数据品质分级

Data-quality grade

计量占比决定等级，等级决定凭证价格与积分系数；不能拿估算数据换 A 级。

判据
q = metered_kWh / (metered_kWh + estimated_kWh) A: q ≥ 0.70 B: 0.45 ≤ q < 0.70 C: q < 0.45
等级计量占比 q价格系数 k积分系数 κ
A≥ 70%1.001.00
B45% ≤ q < 70%0 < k_B < 10 < κ_B < 1
C< 45%0 < k_C < k_B0 < κ_C < κ_B

系数符号必须在合同附件中固定，且只对新批次生效；已签发标签按原版本保留。

可挑战点分母是否包含估算电量、计量窗口是累计还是连续、采样丢失如何计入，三个选择都会改变等级，必须写进规则快照。

MTH-10批次边界

批次完整性

Batch integrity

批次是最小签发单位，不是可拆分的计费单位。

判据
valid_batch ⇔ |B| ≥ 240 ∧ (max t_harvest − min t_harvest) ≤ 24h ∧ harvest_windows(B) = 1

同谱系 24h 内合并为一个批次；一个批次只对应一个采收窗口；禁止拆分套取签发费。

可挑战点240 株下限是运营约束不是统计最优；24h 边界必须为闭区间；客户不共享谱系时该规则不可执行。

MTH-11减排基线

基线共签

Baseline co-sign

减排基线由双方在合同签署时冻结，平台不得单方设定或追溯调整。

判据
B0 = (yield_ref, energy_ref, EF_ref, boundary, period) reduction = (E_ref − E_actual) / E_ref valid_reduction ⇔ sig_client(B0) ∧ sig_platform(B0)

缺任一方签名，不得签发减排声明；基线更新只能通过合同附件，不得在运行期静默替换。

可挑战点共签方是否有能力核验基线、历史数据缺失时用哪个参考年、基线更新是否只能走合同附件。

MTH-12版本治理

版本不可追溯修改

Non-retroactive versioning

方法变更必须发新版本号；旧标签永久指向旧版本，禁止静默重算或覆盖。

判据
version = CJV-MTH-{MAJOR}.{MINOR}[.{PATCH}] MAJOR = 不可变项或语义变化 MINOR = 阈值 / 参数变化 PATCH = 不改变判据的文本勘误

旧标签的 method_version 不可修改；新版本只能生成新标签，不得回写旧记录。

可挑战点什么算“不改变判据的文本勘误”需要白名单；否则 PATCH 会被用来绕过版本记录。
